# 🤝 Contributing to VibeCoding Platform

Merci de votre intérêt pour contribuer à VibeCoding Platform !

## 🌟 Comment Contribuer

### 1. Fork le projet

```bash
git clone https://github.com/votre-username/VIBCO.git
cd VIBCO
```

### 2. Créez une branche

```bash
git checkout -b feature/ma-nouvelle-fonctionnalite
```

### 3. Faites vos modifications

- Écrivez du code propre et bien commenté
- Suivez les conventions de style du projet
- Ajoutez des tests si nécessaire

### 4. Committez

```bash
git add .
git commit -m "feat: ajout d'une nouvelle fonctionnalité"
```

**Format des commits** :
- `feat:` Nouvelle fonctionnalité
- `fix:` Correction de bug
- `docs:` Documentation
- `style:` Formatage
- `refactor:` Refactoring
- `test:` Ajout de tests
- `chore:` Maintenance

### 5. Poussez vers votre fork

```bash
git push origin feature/ma-nouvelle-fonctionnalite
```

### 6. Ouvrez une Pull Request

- Décrivez clairement vos changements
- Référencez les issues liées
- Ajoutez des captures d'écran si UI

## 📋 Checklist PR

- [ ] Code testé localement
- [ ] Tests ajoutés/mis à jour
- [ ] Documentation mise à jour
- [ ] Pas de conflit avec main
- [ ] Commit messages clairs

## 🐛 Reporter un Bug

Ouvrez une [issue](https://github.com/votre-repo/issues) avec :
- Description claire du bug
- Étapes pour reproduire
- Comportement attendu vs actuel
- Screenshots si applicable
- Environnement (OS, Node version, etc.)

## 💡 Proposer une Feature

Ouvrez une [discussion](https://github.com/votre-repo/discussions) avec :
- Description de la feature
- Cas d'usage
- Bénéfices attendus
- Mockups si UI

## 🎨 Style Guide

- Utilisez TypeScript
- Suivez les règles ESLint
- Utilisez Prettier pour le formatage
- Nommage : `camelCase` pour variables, `PascalCase` pour composants

## 🧪 Tests

```bash
# Unit tests
npm test

# E2E tests
npm run test:e2e
```

## 📝 Documentation

Mettez à jour la documentation si vous :
- Ajoutez une nouvelle feature
- Modifiez une API
- Changez une configuration
